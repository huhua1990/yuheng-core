# Yuheng Requirement to Spec

将用户的原始需求转换为正式的需求规格说明书。

## 输入

- 用户口头描述的需求
- 会议纪要
- 需求文档草稿

## 输出

- 正式的需求规格说明书
- 包含：功能需求、非功能需求、约束条件、验收标准

## 执行流程

### 1. 需求收集

询问用户以下关键问题：

- 这个功能的目标用户是谁？
- 要解决什么业务问题？
- 主要业务流程是什么？
- 有哪些约束条件？
- 如何验证功能是否完成？

### 2. 需求分析

基于收集到的信息，分析：

- 功能范围（做什么，不做什么）
- 数据模型（需要哪些表和字段）
- 接口设计（需要哪些 API）
- 前端页面（需要哪些页面和组件）

### 3. 生成规格

生成包含以下章节的规格文档：

```markdown
# 需求规格：{功能名称}

## 1. 概述
- 功能描述
- 目标用户
- 业务价值

## 2. 功能需求
### 2.1 功能列表
### 2.2 业务流程
### 2.3 数据模型

## 3. 接口设计
### 3.1 后端 API
### 3.2 前端页面

## 4. 非功能需求
- 性能要求
- 安全要求
- 可用性要求

## 5. 约束条件
- 技术约束
- 业务约束

## 6. 验收标准
- 功能验收
- 性能验收
```

### 4. 用户确认

提交规格文档给用户审核，收集反馈并修改。

### 5. 冻结规格

用户确认后，将规格状态标记为 `FROZEN`，可以进入下一阶段。

## 使用方法

```
用户："我需要实现用户管理功能"
AI：进入需求收集流程...
```

## 相关规则
