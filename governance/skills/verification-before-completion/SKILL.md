# Yuheng 完成前验证

遵守 [SDD 契约](../yuheng-workflow-router/references/sdd-contract.md)，没有本次实际证据就不宣称通过。
沿用 `workId`、REQ/AC/T、既定规格/计划/证据路径和 `codeVersion`、`governanceVersion`、`knowledgeVersion`。
验证不授予提交、推送或发布权限；已有授权继续有效，仅在其明确范围内执行后续动作。

## 逐项核验

1. 读取实际规格、计划、确认依据和当前 diff，核实本次文件范围、已有修改、兼容影响与未完成任务。
2. 建立 REQ → AC → T → 测试/日志对应关系；每个 AC 至少有一个任务和验证记录，不用“代码已写”代替结果。
3. 从实际工程配置选择证明该结论的命令，确认工作目录、版本、依赖和目标环境，不编造脚本或执行入口。
4. 实际运行适用检查并读完整结果、退出码与用例数；失败、零用例、被跳过或只跑子集均须说明，不能外推全量通过。
5. 把结果写入 `docs/verification/<workId>/verification.md` 或用户指定路径，再按本次阶段给出结论。

## 证据能证明什么

| 拟声明内容 | 所需证据 |
|---|---|
| 行为修复 | 对应 AC 的实际断言与相关回归；适用时包含真实红灯/绿灯 |
| API 验收 | [API 验证](../yuheng-api-verification/SKILL.md) 的方法、参数、响应、权限及适用租户证据 |
| 页面验收 | [UI 验证](../yuheng-ui-verification/SKILL.md) 的实际操作、截图与网络/控制台结果 |
| 迁移或兼容 | 已定位的脚本/配置、实际适用命令和影响验证；不编造 Liquibase 入口 |
| 治理文档或技能 | 当前任务要求的结构校验、真实链接解析和适用情景验证，不能推断业务系统通过 |

构建通过仅证明对应构建；模拟联调只证明模拟范围，手工检查明确方式，退出码记 `N/A（手工操作）`。
记录每条 AC/T 的实际命令、时间、退出码、日志位置及未验证项；示例输出、预期结果和待执行命令不能冒充证据。
后端行为红灯须为测试实际执行后的目标断言失败；`method not found`、编译或环境错误均不是行为红灯。
完成 [自检](../yuheng-self-review/SKILL.md)，确认真实 diff、追踪关系和技术契约；已有检查可引用，不凭空重复生成产物。

## 门禁与交付

- `PASS`：本阶段必需证据完整且已核实，结论仅覆盖已验证范围。
- `WARN`：只有不影响当前阶段的缺口，明确风险和后续动作；不得隐藏验收失败。
- `BLOCKED`：必需输入、决策或验证证据缺失，或必需验收失败；禁止进入依赖阶段。
- `WAIVED`：按契约记录明确授权、负责人、范围、风险、到期和后续任务，未验证事实仍保留。

环境不可用时记录真实错误、受影响 AC/T、未验证范围和补验命令；可报告实现状态，不能宣称全部完成。
无关页面、迁移等写 `N/A` 和理由，不为凑清单创建固定 CRUD 产物，不为转绿改变验收标准。
最终报告实际变更路径、验证结果、证据路径和局限；提交、推送、发布及真实环境操作按本次用户授权执行。
