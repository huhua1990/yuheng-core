# Yuheng 行为测试先行

遵守 [SDD 契约](../yuheng-workflow-router/references/sdd-contract.md)，规格/计划门禁不能被测试步骤替代。
沿用 `workId`、REQ/AC/T、确认依据及 `codeVersion`、`governanceVersion`、`knowledgeVersion`，仅实现当前授权范围。
后端行为变更先观察针对目标行为的断言失败，再写最小实现；前端逻辑测试结合浏览器验收，纯样式采用可重复视觉检查。

## 选择测试

1. 从 AC 和任务 T 提取一个可观察行为，定位真实测试框架、模块、依赖及已有用例，命令来自当前工程配置。
2. 核对被测类型、方法签名和测试数据；优先测试实际边界，mock 仅隔离依赖，不能只断言 mock 返回自己设置的值。
3. 新接口需先有最小可编译声明或无目标业务逻辑的骨架，并记录准备步骤；准备失败不算红灯。
4. 测试入口或环境不可用时先记录阻塞和补验动作，可推进独立分析，不能以编译错误替代行为验证进入依赖实现。

## 红灯 → 绿灯

- 运行目标测试，检查实际收集的用例数、失败断言、期望和实际结果，确认失败正好对应本次 AC。
- `method not found`、`cannot find symbol`、编译/导入失败、零用例、依赖解析或启动/连接失败均不是有效红灯。
- 修正入口或环境后重跑，直到测试实际执行并在目标断言失败；不伪造错误日志，也不制造无关异常凑红灯。
- 红灯已确认后写满足该行为的最小实现，保留原有 HTTP、响应、权限和租户契约，不附带无关重构。
- 重跑同一用例确认绿灯，再执行受影响的相关回归；若整理实现，整理后重跑相关测试。
- 测试一开始就通过时，确认目标行为是否本已存在或断言未覆盖差异，不把它写成经历了红绿循环。
- 实现已先写时如实记录顺序缺口，不能补造先前红灯；安全可逆时隔离本次行为修复验证回归测试，保留他人已有修改。

## 判定示例

例如已存在且可编译的唯一性校验入口，测试断言重复值返回规定业务错误，实际未拒绝：这是目标断言红灯。
若调用了不存在的 `create` 方法导致编译失败，测试尚未运行：先核对真实 Service 接口，不算“方法未实现所以红灯”。
以上是判定说明，不是执行结果；只有真实运行日志能进入验收证据。

## 证据与出口

在 `docs/verification/<workId>/verification.md` 或用户指定路径记录测试文件/用例、AC/T、红灯原因和最小实现范围。
记录红灯、绿灯和回归的实际命令、执行时间、退出码、用例结果与日志；前置环境错误单独列出，不混入断言证据。
后端按 [API 验证](../yuheng-api-verification/SKILL.md)、前端按 [UI 验证](../yuheng-ui-verification/SKILL.md) 补充适用验收。
必需行为测试或红绿证据缺失为 `BLOCKED`；豁免须按契约明确授权，豁免仍不等于测试通过。
业务或契约变化先取得对应差异决策，范围内技术细节沿用既有授权；不因测试失败降低 AC 或删除失败用例。
交付前执行 [完成前验证](../verification-before-completion/SKILL.md)，不默认提交、推送、发布或操作真实环境。
