# 后端代码修改必须附带单元测试

修改任何后端 Java 代码后，**必须**同步添加或更新对应的单元测试。

---

## 强制要求

1. **改代码必加测试。** 新增方法、修改逻辑、修复 bug，都必须有对应的单元测试覆盖。

2. **测试必须能跑过。** `mvn test -Dtest=XxxTest` 全部通过后才能说"完成了"。

3. **不能依赖人工验证。** 不能在没跑测试的情况下让用户去手动试。

4. **纯单元测试优先。** 业务分支优先用 JUnit + Mockito，减少对数据库和 Spring 容器的依赖。SQL、迁移和租户过滤的正确性仍须使用适当的集成验证；纯单测不能替代数据库验收。

5. **测试放对位置。** `src/test/java/` 下镜像 main 的包结构。

---

## 测试最小覆盖

| 改动类型 | 最小测试要求 |
|----------|-------------|
| 新增工具方法 | 正常路径 + null 输入 + 边界值 |
| 新增/修改异常处理逻辑 | 触发异常的输入 + 验证返回的错误码和消息 |
| 修改 DTO/VO 字段 | 验证序列化/反序列化不丢字段 |
| 修改 Service 业务逻辑 | 主要分支覆盖 |
| 修改 Mapper/XML | 至少一条 SQL 正确性验证 |

---

## 示例

修改了 `UserService` 的创建逻辑 → 必须写 `UserServiceTest`，覆盖：
- 正常创建 → 成功
- 用户名重复 → 失败
- 参数校验 → 失败

---

## 禁止事项

- 改完代码说"已完成"但没跑测试
- 用"环境限制/数据库连不上"作为不写测试的理由
- 让用户人工试了再回来报 bug
